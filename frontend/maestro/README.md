# Сценарии нативного приложения (Maestro)

Сквозные проверки iOS-приложения на симуляторе (ADR-0014). Maestro управляет симулятором как пользователь: видит и нативные окна iOS, и содержимое WebView.

| Сценарий | Что проверяет |
|---|---|
| `launch.yaml` | Приложение запускается на экране входа с кнопками Google и Apple |
| `sign-in.yaml` | Тестовый аккаунт входит через «Вход для проверки», профиль загружается |
| `microphone.yaml` | Тема открывается, кнопка микрофона запускает запись (тег `needs-microphone`: в CI не запускается, у раннеров нет микрофона) |
| `common/sign-in.yaml` | Общий шаг входа, используется другими сценариями |

Запуск на маке владельца:

```bash
just e2e-ios                       # собрать приложение для симулятора и прогнать все сценарии
scripts/test-app.sh ios            # прогнать сценарии на уже собранном приложении
scripts/test-app.sh ios microphone.yaml
```

Нужны Xcode, Java 21 и Maestro (`brew install mobile-dev-inc/tap/maestro`). Почта и пароль тестового аккаунта берутся из Связки ключей (запись `turktalk-review-login`, её создаёт `scripts/create-review-account.sh`), в CI из секретов `REVIEW_LOGIN_EMAIL` и `REVIEW_LOGIN_PASSWORD`. Скрипт не печатает пароль; Maestro пишет набранный текст в свои отладочные логи, поэтому `scripts/test-app.sh` маскирует пароль в них и кладёт логи в `artifacts/maestro/last-run`.

В CI сценарии запускаются каждую ночь и по кнопке: workflow `.github/workflows/app-e2e.yml` (Actions → «App E2E (iOS)» → Run workflow).

Ограничения:

- Сценарии ходят в production-бэкенд под тестовым аккаунтом и останавливаются до платных вызовов: ответы не вводятся, запись не отправляется на распознавание. Список запрещённых для сценариев маршрутов — в C-14 (`docs/architecture/constraints.md`).
- Тестовый аккаунт общий с проверяющими магазинов: если там сменят язык на английский или создадут тему на «Банк…», сценарии могут упасть.
- Симулятор берёт микрофон и разрешение у мака, поэтому системный запрос iOS на микрофон может не появиться; шаг с ним необязательный. Сам запрос и качество распознавания живой речи проверяются на настоящем iPhone.
- Вход через Google и Apple не автоматизируется: там пароли, коды и подтверждения на других устройствах.
- iOS-приложение требует бэкенд с поддержкой `platform: "ios"`; бэкенд выкатывается раньше приложения.
