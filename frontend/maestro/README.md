# Сценарии нативного приложения (Maestro)

Сквозные проверки iOS-приложения на симуляторе (ADR-0014). Maestro управляет симулятором как пользователь: видит и нативные окна iOS, и содержимое WebView.

| Сценарий | Что проверяет |
|---|---|
| `launch.yaml` | Приложение запускается на экране входа с кнопками Google и Apple |
| `sign-in.yaml` | Тестовый аккаунт входит через «Вход для проверки», профиль загружается |
| `microphone.yaml` | Тема открывается, кнопка микрофона запускает запись, «Завершить запись» отдаёт запись на распознавание, и в поле ответа появляется «Merhaba, hesap açmak istiyorum.» без ошибки |
| `common/sign-in.yaml` | Общий шаг входа, используется другими сценариями |

Запуск на маке владельца:

```bash
just e2e-ios                       # собрать приложение для симулятора и прогнать все сценарии
scripts/test-app.sh ios            # прогнать сценарии на уже собранном приложении
scripts/test-app.sh ios microphone.yaml
```

Нужны Xcode, Java 21 и Maestro (`brew install mobile-dev-inc/tap/maestro`). Почта и пароль тестового аккаунта берутся из Связки ключей (запись `turktalk-review-login`, её создаёт `scripts/create-review-account.sh`), в CI из секретов `REVIEW_LOGIN_EMAIL` и `REVIEW_LOGIN_PASSWORD`. Скрипт не печатает пароль; Maestro пишет набранный текст в свои отладочные логи, поэтому `scripts/test-app.sh` маскирует пароль в них и кладёт логи в `artifacts/maestro/last-run`.

В CI сценарии запускаются каждую ночь и по кнопке на маке владельца (свой раннер с меткой `turktalk-mac`): workflow `.github/workflows/app-e2e.yml` (Actions → «App E2E (iOS)» → Run workflow).

Тестовая сборка (ADR-0014). `scripts/build-ios.sh sim` собирает веб-часть с `VITE_TEST_AUDIO=true`. В такой сборке:

- вместо микрофона записывается встроенная фраза `frontend/src/testBuild/phrase.m4a` (голос macOS «Yelda», около 15 КБ, 2,6 секунды; проигрывается по кругу, пока запись не остановят), а `MediaRecorder` кодирует её как обычную запись;
- запрос `POST /api/transcriptions` не уходит в сеть: приложение проверяет запись (тип audio/*, не меньше 1000 байт) и возвращает готовый ответ с текстом «Merhaba, hesap açmak istiyorum.». Пустая или битая запись даёт ошибку распознавания, и сценарий падает. Другие запросы не подменяются.

`microphone.yaml` помечен тегом `needs-test-build`: `scripts/test-app.sh` запускает его только на iOS и только если в устанавливаемом `App.app` есть метка `turktalk-test-audio-build`. Иначе (нет собранного приложения, уже установленное приложение из Xcode, старая сборка, Android) сценарий пропускается с сообщением, остальные идут как обычно: на обычной сборке запись ушла бы на платное распознавание.

Диктовка отзыва в настройках тестовой сборкой не подменяется: её запись ушла бы на `/feedback/transcribe` (платно), поэтому сценарии её не используют.

В обычные сборки (веб, Android, App Store) этот код и файл не попадают: флаг принимается только из окружения (из `.env`-файла сборка его отвергает), а `frontend/build/checkNoTestAudio.mjs` проверяет `just frontend-build` (веб и нативный режим без флага), `frontend/ios` после `sync`, `open` и `sim`, и веб-часть в сборке Android перед Gradle. После `sim` скрипт возвращает в `frontend/ios` обычную сборку.

Ограничения:

- Сценарии ходят в production-бэкенд под тестовым аккаунтом и останавливаются до платных вызовов: ответы не вводятся, кнопка проверки ответа не нажимается, запись не уходит на сервер (см. «Тестовая сборка»). Список запрещённых для сценариев маршрутов — в C-14 (`docs/architecture/constraints.md`).
- Тестовый аккаунт общий с проверяющими магазинов: если там сменят язык на английский или создадут тему на «Банк…», сценарии могут упасть.
- Тестовая сборка не открывает микрофон, поэтому системный запрос iOS на микрофон не появляется; шаг с ним необязательный. Настоящий микрофон, сам запрос, обработка аудио сервером и распознавание живой речи проверяются на настоящем iPhone.
- Вход через Google и Apple не автоматизируется: там пароли, коды и подтверждения на других устройствах.
- iOS-приложение требует бэкенд с поддержкой `platform: "ios"`; бэкенд выкатывается раньше приложения.
