# Conversion roadmap

The codebase started as SerboTalk, a Russian/English → Serbian trainer running on OpenAI. It is being converted to a Turkish trainer running on Claude and ElevenLabs. "Planned (Phase N)" in the views refers to these phases.

| Phase | Outcome | Status |
|---|---|---|
| 0 | Architecture documentation and agent guardrails (this directory, `AGENTS.md`, `CLAUDE.md`, agent sandbox, secret scanning) | Done |
| 1 | Tooling baseline: `uv` + lockfile, Ruff, Pyright, Biome, pinned frontend dependencies, `justfile`, GitHub Actions, architecture checks | In progress: backend done; frontend: pinned dependencies, `justfile`, CI and architecture checks (dependency-cruiser, ESLint) and Biome formatting done |
| 2 | Claude and ElevenLabs adapters behind the provider ports; usage ledger; budget guard with a $25 monthly cap on every AI entry point | Done in the backend, tested with fakes; live providers not yet exercised. Client "practice paused" message done for answer check, speech-to-text and review-phrase preparation. Custom topic creation too, since ADR-0008 added the failure reason to its error |
| 3 | Turkish language: text policy, prompts, `_sr` → `_tr` rename, re-authored content, grading eval | In progress: text policy, prompts, rename, OpenAI removal and Turkish content (210 phrases, hints, 50 skills, fallback exercises) done; native-speaker review of the content and the grading eval pending (eval needs provider keys, run before deployment). The Turkish product starts from a fresh database: `seed` refuses a database that holds skills from the Serbian catalogue |
| 4 | Frontend restructure: Tailwind v4 tokens, shadcn/ui, TanStack Router and Query, i18next, `App.tsx` split by feature | In progress: Serbian alphabet toggle removed (`serbianScript.ts` replaced by `turkishText.ts`), budget-paused message, mocked e2e spec repaired, green locally and a required CI job. Tailwind v4 with design tokens and shadcn/ui components in `src/shared/`; the inherited stylesheet sits in a lower cascade layer and shrinks screen by screen; Settings migrated; practice screen extracted into `features/practice/` and redesigned in the tea-house world (Impeccable critique, roll and finish review; ADR-0003 amendment); app shell (headers, topic chooser, welcome and completion states) moved to `features/shell/` on the tokens, and every colour left in the legacy stylesheet mapped onto the tokens, so the remaining legacy screens render in the tea-house palette too. Statistics moved to `features/statistics/` on the tokens. Premium and the custom topic and phrase forms moved onto the tokens and shared Input/Select/Field components. Settings sub-sections, the admin pages, the login card and the legal pages followed. The payment form (reworked with the payment country in Phase 5), the reward overlay and the landing page still use legacy CSS; module boundaries enforced by dependency-cruiser (C-20, C-22) and a locale parity test (C-19). i18next stable keys done for the application interface: catalogues `src/locales/{ru,en}/ui.json` with Russian plural forms; the legacy dictionary remains for Russian content from the backend and for the landing and legal pages (Phase 5). `App.tsx` split started: sign-in moved to `features/auth/AuthGate.tsx`, word hints to `features/practice/useWordHints.ts`, voice recording and transcription to `features/practice/useVoiceAnswer.ts` (both with race tests), and the practice session itself (catalogue, startup phrase, answer checking, next phrase) to `features/practice/usePracticeSession.ts`; App.tsx keeps navigation, app lifecycle and rendering; the open Premium form survives the phone/desktop layout switch. Data layer started: TanStack Query with one client per signed-in account (`shared/lib/QueryProvider.tsx`; no silent retries, no refetch on focus) for statistics, the admin user and payment lists and the custom phrase list; the practice flow, whose catalogue load starts the first session and whose request races must stay as they are, keeps its own handling. TanStack Router not started |
| 5 | Rebrand to the working name TurkTalk and move to the owner's own infrastructure | Not started |
| 6 | UX verification with the Impeccable skill, accessibility checks and screenshot baselines | Not started |

Update the Status column as phases land.
